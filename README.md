# Environmental Management Skills Taxonomy (EMST) v2

EMST is an open, versioned, machine-readable taxonomy of the work, capabilities and roles of the environmental sector, built so the sector can see how its jobs are changing and so people, skills and knowledge can move between federal, state, local, Tribal, NGO, private and academic institutions (`CHARTER.md`). This repository is the single source of truth: every release format is generated from the source records here.

> **Status: Phase 4 build, pre-release.** Nothing here is validated by subject-matter panels yet. Records drafted by agents are draft evidence (`validationStatus: draft`, evidence label S for ratings). EMST describes work; it is not a selection instrument, not a classification basis, not a job analysis and not for RIF, adverse action or performance-rating decisions. Indigenous knowledge is a distinct body of expertise held and governed by Indigenous nations and is out of scope by design; nothing Tribal-related is published before a Tribal Advisory Council approves (ADR-0007).

## Where things are

| Path | What |
|---|---|
| `docs/standard/SPEC.md` | the normative v2 specification |
| `docs/standard/AUTHORING_GUIDE.md` | how to write records: locations, minimal examples, seed keys, minting, validation, held content |

| `data/v1_baseline/` | frozen, hash-pinned v1 extract (never edited) |
| `legacy/v1/` | verbatim v1 material |
| `scripts/` | `build_schema.py`, `validate_v2.py`, `mint_id.py`, `migrate_v1.py`, `build_release.py`, `update_readme_status.py` |
| `docs/research/`, `docs/audit/` | team research and the v1 audits |

## Working with the data

```bash
pip install -e ".[dev]"
python scripts/build_schema.py --check        # schema current with vocab/
python scripts/validate_v2.py                 # every record and cross-record rule (exit 1 on error)
python scripts/migrate_v1.py --check          # v1 seeds and the X1 crosswalk are reproducible
python -m pytest -q                           # tests incl. seeded-violation fixtures
python scripts/build_release.py --profile preview --version 2.0.0-dev   # internal preview build into dist/
```

Releases are built by `scripts/build_release.py` (JSON-LD bundle, CSV + Frictionless data package with an HCM import file and delta feed, SKOS Turtle, SSSOM, computed views, generated release notes, SHA256SUMS); two builds from the same inputs are byte-identical. Held Tribal-related content and drafts without minted IDs are excluded by the release gate.
