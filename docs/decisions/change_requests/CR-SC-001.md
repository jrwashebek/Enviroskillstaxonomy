# CR-SC-001: Task-level sensitivity edges, instrument roles on enactments, competency mirror links, and the venue-applicability rule

- **From:** SC (A5, with SL), WP-05 · **To:** CA (decider), DE and IA (schema, validator, build) · **Date:** 2026-10-23 · **Type:** X (structural; schema and computed view) · **SemVer impact:** minor (new optional fields; one new rule file)
- **Affects:** SPEC §5.2, §5.4, §5.5, §5.16, §11.6; `schema/src` `Task`, `SensitivityEdge`, `Enactment`, `Competency`; `scripts/build_release.py`; `vocab/rules/`; ADR-0016 §3-4; ADR-0028 §3
- **Evidence label:** J (SC; found by authoring WP-05 against the schema after the ADR-0029 rulings)

## Problem

1. **Tasks cannot carry sensitivity edges.** SPEC §5.16 and ADR-0028 §3 say tasks *and* competencies link to mechanisms through `instrumentSensitivity` edges. The schema has `instrumentSensitivity` on `Competency` only. WP-05 was asked for "sensitivity edges from tasks to L5 instruments". The edges are in `docs/build/WP-05/generated/task_sensitivity_edges.csv`, generated by `docs/build/WP-05/gen_edges.py`. Each primary task inherits its competency's mechanism edges and is joined to the registered instruments of that competency's actor enactments that share the mechanism. These are draft assertions waiting for per-task review.
2. **Instrument links say nothing about the instrument's role.** `Enactment.characteristicInstruments[]` is a plain reference list, so a computed view cannot tell whether an instrument *requires* the work, *enables* it, *constrains* it or *removed* an earlier requirement. The prototype view shows the defect. `seed:ena-sl-c08-federal` links the in-force rule that **removed** the government-wide NEPA regulations, and the view reads that rule as a "required basis" for environmental review. ADR-0016 §3 needs this distinction: federal default profiles flag items whose only basis is a rescinded or inactive instrument.
3. **No home for mirror links between competencies.** WP-05 acceptance asks that "every regulatory competency has regulator and regulated-party mirror links where they exist". `emst:mirrorRole` is defined only between role variants (an SSSOM predicate). Where both sides sit in one competency, the mirror is visible through actor enactments with different `authorityPosition` values (SC-C07, FH-C01, DB-C50, SC-C14, SC-C17). Where the sides are separate competencies (SL-C03 inspection and DB-C26 facility compliance; SL-C02 permit issuance and the SC-C01 applicant enactment; SC-C04 agency oversight and the SL-C08 preparer enactment), no field can hold the link. WP-05 records these pairs in `docs/build/WP-05/mirror_links.csv` and in editorial notes.
4. **The venue-applicability rule is not implemented.** ADR-0016 §3-4 asks views to compute `venueApplicability` and `federalApplicability` from instrument status. No rule file or build step exists yet. WP-05 wrote a prototype, synthetic fixtures and tests:
   - `docs/build/WP-05/ci/venue_applicability.py`
   - `ci/fixtures/` (the fixtures validate with `validate_v2.py --data-root`)
   - `ci/test_venue_applicability.py` (6 tests pass)
   Its output for the live data is in `docs/build/WP-05/generated/`.
5. **"Delegated constraints" has no field.** The brief asks for structured actor enactments covering authority basis, principals and delegated constraints. WP-05 writes the constraints inside `authorityBasis` after the label "Delegated constraints:". An example is `seed:ena-sl-c02-state-regulator`.

## Proposed change

1. Add `instrumentSensitivity` (the existing `SensitivityEdge`) to `Task`, as SPEC §5.16 already says. WP-05 will then convert the generated edge table into task records after a per-task review. The CI rule for `reviewBy` on edges (P-SC-14) applies to both.
2. Make each `characteristicInstruments[]` item an object `{instrument, role ∈ requires | enables | constrains | removed-requirement}`, or add a parallel `instrumentRoles[]`. The venue rule would then count only `requires` toward `required-basis`. Today WP-05 links only registered IDs and leaves roles implicit.
3. Add an optional `Competency.mirrors[] {competency, relation ∈ regulated-party-mirror | preparer-mirror | overseer-mirror}`, stored on the regulator-side record only, with the inverse computed under `inverse-links@1.1.x`. The alternative is to extend `emst:mirrorRole` to competencies in an SSSOM set `emst-mirror` owned by IA. Either way, `mirror_links.csv` is the migration source.
4. Port the prototype to `vocab/rules/venue-applicability@0.1.0.yaml` plus `scripts/build_release.py`, and move the fixtures and tests into `tests/`.
   - Proposed draft rule:
     - `required-basis` if any linked `requires` instrument is active (`in-force`, `in-force-litigated`, `interim-in-force`, `issued`).
     - `no-current-basis` if every linked instrument is inactive (`enjoined`, `stayed`, `vacated`, `rescinded`, `repealed`).
     - `permitted` otherwise.
   - Tribal enactments are never read.
   - The view also reports `basisLinked`.
   - Q4 default: show the value with a note; exclude nothing.
5. Either add `Enactment.delegatedConstraints` (Text), or ratify the "Delegated constraints:" convention inside `authorityBasis`.

## Also for WP-10 (LM): instruments to register

`docs/build/WP-05/instruments_to_register.csv` lists the instruments that WP-05 enactments need but the registry lacks, with citation hints and proposed seed IDs. Three entries were verified this session from primary or near-primary sources:

- the EJ executive orders and their January 2025 revocations [E: WP05-001];
- New Jersey's EJ law and rules, affirmed on 2026-01-05 [E: WP05-003];
- New York's ECL 70-0118 and the SEQR amendments effective 2026-06-12 [E: WP05-002].

EO 14303, also verified [E: WP05-004], supports the integrity enactment. Until these entries are registered and linked, the DB-C52 federal value computes as `permitted` with `basisLinked = false`.

## Consequences if not accepted

The task-level edges stay in a CSV outside the validated tree, and the mirror links stay in prose and a CSV. The venue view over-reads enabling and removal instruments as a required basis. ADR-0016's federal default view can then show a wrong applicability value with a confident label.
