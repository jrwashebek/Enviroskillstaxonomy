## Context

S1 content authoring is finished: FC, DC, SC, DB, LC/IO and IA wrote 159 live core competency records, nine wave-1 module sections, the L4 seed, the credential register and 11 staged pathways. The agents chose reversible interim encodings where the schema had no home and filed seven CRs:
- task-level sensitivity edges;
- untyped instrument links that make the venue view misread rescissions as a basis;
- mirror links;
- pathways that cannot reference roles not yet written;
- untyped formation provisions;
- no CLO address;
- a missing closure type;
- no three-module check;
- no Enactment subsectors;
- a case-insensitive product lint.

Three of the CRs (CR-FC-001, CR-FC-002, part of CR-DB-001) are content handoffs to WPs that have finished, so the CA must say who writes them and when.

### 2. Rules that bind every lane from now on

1. **Link roles live on links.** Wherever an L1–L3 record cites an L5 instrument, the link carries a role. Computed applicability reads only `requires`.
2. **Inherited facts are computed.** A task does not store an edge, a subsector or a mechanism that it inherits unchanged from its competency, and an indicator does not store its competency's subsectors.
3. **A link between two EMST records is stored once, on one named side.** Mirrors are stored on the authority or overseer side. SSSOM sets are for external crosswalks only.
4. **The generic CLO is craft-neutral.** Enactment indicator variants extend a CLO only inside that enactment.
5. **What a job analysis measures is not shown until a person has measured or reviewed it.** Agent-drafted importance, time shares and critical or entry flags stay in the data with their status and render as "assessment pending". Role-design values (bundle membership and target levels) render labelled as editorial drafts.
6. **Views read released records only.** No view, kit or explorer page computes from `data/v2/` or from an authoring folder; the release gate runs first.

## Rationale

- **Typed links fix the venue defect at its cause.** The defect came from asking one untyped list to say two things, which instruments exist and what they do to the work. LM showed that the registry cannot carry the role, because one rule can require one actor's work and remove another's. Counting only `requires` makes the view monotone in the right direction: a revoking order can never create a basis.
- **Zero enactments.** Requiring enactments for uniform performance would force authors to write empty enactment records. The three-module test is about recurrence of a task core, which the build can compute.
- **DB-C53** follows the home-module rule (ADR-0018 §6). The deliverable's sufficiency is governed by laboratory accreditation and methods wherever the data go. The part that genuinely recurs, the data user's review, is already a core practice.
- **Merges.** The five merges all fold a generic or single-practice v1 item into an environmental survivor. That is exactly what G-8 and the knowledge-area test require, and none of them touches ADR-0016's or ADR-0007's protected content.
- **Freezing the builders** is the only way several agents can edit one record set in S2 without silent loss.

## Consequences

- SPEC 2.0.0-draft.3. After DE's rebuild, the schema is 2.0.0-draft.3.
  - `build_schema.py --check` reports `v_closureType` STALE until DE regenerates.
  - The new vocabulary keys (`instrument_link_roles`, `mirror_relations`, `formation_responses`) are not yet wired, so they do not make the check stale.
  - Data validation is unaffected: 0 errors on 2026-10-23.
- 49 enactments change shape when DE converts them, with no change of meaning. Until SC and DB set roles, the venue view reports their links as `untypedLinks` and decides nothing from them.
- The core projection is 175 after the merges, with 21 rows still to author in S2–S3. rc.1 will be smaller if any are not written; the release notes count them.
- `questions_for_project_lead.md` is unchanged. Q4's default (show computed applicability with a note, exclude nothing) is now implementable correctly.

## Dissent and trade-offs

- **SC:** inherited task edges would have been visible in task records. Accepted cost: they are visible in the computed view instead, and only reviewed, task-specific edges are stored.
- **DB:** keeping DB-C53 in a wave-2 module leaves laboratory roles without rc.1 content. Accepted: no P1 or P2 role is a laboratory analyst. R24 and R26 get the data-user side in core.
- **LC:** `responses[]` as an array is less strict than one response per provision. It is accepted because real provisions combine supervised repetitions with a validation drill.
- **FS, CM:** the merge list leaves FS-C15 and CC-CM-02 standing; the CA judged headroom of five sufficient without touching ADR-0025 or ADR-0023 content.
- **Trade-off named:** central S2 work orders put more load on WP-08's agents. The alternative, reopening five finished WPs, would compete with the S2 critical path and with the builder freeze.
