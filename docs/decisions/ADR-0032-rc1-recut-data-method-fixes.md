## Context

An independent data and methods review of the unreleased 2.0.0-rc.1 found that several stored values claim more than their evidence supports: LLM-assisted v1 tags labelled as expert judgment, one model's repeated passes recorded as three raters, signals counted as independent when they share an upstream dataset, directions the stored intervals do not support, lifecycle states that read as validation, crosswalk rows that assert matches they record as "no term found", and HR views built on related-match candidates. rc.1 was never tagged or distributed, and every rc.1 ID is still `candidate`, so the fixes go into the data and rc.1 is re-cut from a clean commit. No ID is changed or reused (ADR-0010). The counts below come from the scripts named, run on 2026-10-25; none is typed from memory.

### 2. Lifecycle (M7; CR-CA-001)

- **Meaning.** The lifecycle state describes the *work* in the sector; `validationStatus` describes the *record*. `established` now reads "Long-standing work in the sector; EMST content validation is tracked separately in validationStatus." The old meaning is kept in the vocabulary as `meaning_before_2026_10_25`.
- **No cap.** Lifecycle no longer caps the use tier (`max_use_tier` removed; effective-use-tier@1.1.0). The tier is capped by the evidence of ADR-0024, `validationStatus` and the display gate. Only `withdrawn`, `lapsed` and `merged` records, which are not current, have no tier.
- **Entry tests.** The tests of ADR-0015 are now machine-readable (`vocab/lifecycle_states.yaml#lifecycle_states.<state>.entry_test`). A `proposed` or `emerging` record from `candidate` stores a `lifecycleBasis` with the test, the evidence and the counts, and the validator recomputes the counts from the cited evidence (`E-LIFECYCLE-BASIS`; a warning on drafts). `watch` may now label L1–L4 records whose work is hypothesized.
- **Result.** No record met a test: the signals behind each proposed or emerging record (0 to 4 of them) reduce to at most one independent signal under ER-1, and none cites ten postings or PDs, a mandate in force or an operating programme with a resolving E source. 440 records moved to `watch`, each with a `not-met` basis and `reviewBy` at most 12 months out: 8 role profiles, 26 competencies, 44 role variants, 147 tasks, 201 indicators, 3 enactments and 11 pathways (`docs/build/rc1-fix/generated/lifecycle_changes.csv`). The eight roles are listed in `DATA_DONE.md`; the package must be updated for them.

### 3. Conservative choices where the brief did not choose

| Question | Options in the review | Chosen | Why |
|---|---|---|---|
| Lifecycle test scope | roles and competencies (brief) or every L1–L4 type | **every L1–L4 type** | The brief names roles and competencies. Tasks, indicators, variants, enactments and pathways carried the same unsupported states, and leaving them would let a child record claim `emerging` work that its role cannot. One rule for all types is the more cautious reading. |
| One observation, several targets | one record with `targetIds[]`, or `observationId` on each record | **`observationId`** | No record is merged, so no candidate ID is deprecated before 2.0.0; counts report distinct observations. |
| NoTermFound convention | `predicate_modifier: Not`, or no positive predicate | **the searched SKOS predicate with `Not`** | It keeps what was searched for, is plain SSSOM 1.0, and a reader who ignores the modifier still sees no object. `emst:successorNotReleased` covers withheld successors. |
| Rows below closeMatch in FSP and SCV | exclude, or show in a section labelled "unreviewed agent candidates (not an alignment)" | **exclude and count** | Hide rather than show. The count tells a reader something was left out. |
| State class views per class | one file per variant, or one per class | **one per class with `variants[]`** | One class code, one file; three variants on one class no longer overwrite each other. |
| Projection reading when absolute and relative change disagree | grow, or indeterminate | **indeterminate** | A positive projection below the all-occupation baseline is not growth in the sector's share. |
| OBS-4 | null until coded, or an L5 llm rating | **null, with `obs4Draft`** | A null cannot be exported as a measurement; the draft keeps the agent's work for IO's coders without a new rating type. |
| L5 spans without L5 indicators | cut the span, or `levelSpanBasis: declared` | **cut to L4, and record the basis** | SPEC §8.2 rule 2 defines L5 only where an SME panel confirms demand; no panel has met. |
| State class hashes | fetch and hash, or `url-only` | **`url-only`** | The pass reads no new third-party document; it does not claim a hash it did not take. |
| m7 review tasks | author the eight, or lint only | **author eight drafts and lint the rest** | The review named the eight. The other 46 belong to their content owners; the lint warns and never blocks. |
| Stale v1 assessments | store `stale: true`, or compute it | **compute** | SPEC §14: computed fields never appear in source. `assessment_staleness.stale_ids()` gives D-BUILD the bundle flag. |
| Bootstrap percentile in m13 | fix `boot_ci`, or leave it | **leave it** | The stored `ci95` values were made with it and the review calls the error negligible; changing it would make the figures disagree with the data. The new difference interval uses linear-interpolation percentiles. |

## Consequences

- `python3 scripts/validate_v2.py` and `--strict`: 0 errors, 128 warnings. `python3 -m pytest -q tests`: 472 tests pass. 44 tests in `tests/test_rc1_data_fixes.py` would each have caught one of the findings.
- Every change indicator stays `watch` (210 under change-indicator@1.1.0). Effective use tiers in the scratch build: exploratory 1,949, describe 1,781.
- The package overstates the evidence until it is updated: roles and competencies described as emerging, F05/F06 captions, counts of signals and raters, the X2 gate statement and the v1 labelling sentence.
- New records: eight draft review tasks (seed keys `seed:rc1-m7-*`) need IDs minted by the single writer. 41 minted records are now held (3 routed, 38 by inheritance).
- Nothing here is a human review. Every value this pass wrote is agent-made, `draft` or `S`, and cites this ADR.
